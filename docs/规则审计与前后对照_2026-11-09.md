# 清漪行为规则审计与修改前后对照

日期：2026-11-09。范围：QQ 群聊、QQ 私聊、控制台悄悄话、主动行动、模型包装与发送包装、本地桌宠/MAA。

**交付状态：本轮仅修改本地代码，没有部署生产、修改云端配置、重启线上服务或推送任何 Git 远端。** 没有删除她的历史记忆，没有启动 MAA 跑单或消耗游戏资源。

本报告不是新加的一层提示词，也不是“以后所有规则都统一了”的声明。它说明现有规则的真实归属、确认的冲突、实际修复、仍保留的限制。

## 1. 结论

问题不是单纯的“提示词太长”，而是同一个决定被多层重新解释：

- 人设要求“无条件听话”，裁决又给她个人边界；系统消息与用户消息里各有一套优先级宣言。
- 主裁决要求办完整，长度档仍说“三四十字”；模型包装还会先剪掉内容。
- 社交/亲密风格能压住明确委托；工具分类、工具选择、搜索标记又各自决定一次。
- 发不出去与不想发混在一起；一些路径把 `False` 当成功，另一些把临时失败永久算成不说。
- 同话题去重没有完整绑定收件人/来源；重启时预留状态可能永久占着名额。

本轮采用的是**保留现有人格与功能、修复实际冲突、让已有职责分工一致**，不是重写人格内核。

## 2. 现在的职责与优先级

这是经过代码核对的分工，不是一个已经落地的全局统一调度器：

1. **安全、隐私、能力事实、明确禁止条件。** 例如不要联网、别人私聊内容不能换人分享、不能把未完成说成完成。
2. **发言对象与任务归属。** 这条是对谁说的、哪个人请求、结果该送给谁、谁能叫停。
3. **本轮目的。** 闲聊、任务产物、长文、工具交货、私聊亲密/边界、内部结构化处理。
4. **是否愿意表达。** 私聊/真正点名一般回应；群体互动是机会；个人边界可以拒绝；自动机会不等于必须发。
5. **具体事实与执行结果。** 搜索需实体/领域/回答要点/适用时效；工具叙述不自动等于完成证据。
6. **表达与排版。** 称呼、语域、口癖、字数、分条只影响表达，不能覆盖前五层。
7. **投递及记账。** 未确认接受不能冒认已发送；主动发送失败不扣成功额度；“对方看到了”仍通常未知。

主裁决在 [conversation_plan.py:323](bot/conversation_plan.py#L323)，入站与实际执行在 [qq_openclaw_bridge.py:9767](bot/qq_openclaw_bridge.py#L9767)，模型/发送包装在 [ceylan_control_runtime.py:258](bot/ceylan_control_runtime.py#L258)。

### 2.1 真实包装顺序

安装顺序为 keys → control → observer → fun，所以调用时 fun 在最外层，不能只看 control 自己的判断。见 [ceylan_runtime.py:283](bot/ceylan_runtime.py#L283)。

本轮修复后，internal、report、专用输出目的在最外层就会被识别。普通巡群仍受巡群开关、安静时段和巡群调用额度约束；这不代表所有自主 worker 已共享一个总预算。

## 3. 什么时候说、什么时候不说

依据：[conversation_plan.py:78](bot/conversation_plan.py#L78)、[qq_openclaw_bridge.py](bot/qq_openclaw_bridge.py)。

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 私聊/悄悄话 | 私聊主裁决要求回应，但附加背景被统一标成群聊，“插不上就等群友聊”也会注入私聊 | 私聊背景单独标为背景材料，不追加群聊旁听/闭嘴规则 |
| 真正 @ 她 | 直接回复入口 | 保留；安全和个人边界不因 @ 消失 |
| 引用她的话但不带名字/@ | 缓存知道被引用者，但直接入口丢了 `reply_to_user`，可能错进自动概率判断 | 直接入口利用引用归属，把真正回复她的消息识别为直接对话 |
| 提到她的名字但在谈论她 | 不应一律当命令 | 保留原有“讨论她≠叫她办事”的守卫 |
| 明确找另一个人 | 普通回复会防抢答，但画图/唱歌/语音分发可能已经先执行 | 工具和随机语音回复之前先判归属，不执行别人的委托 |
| 群体玩梗/斗图/共同话题 | 可加入，FORCE 参数可增加参与机会 | 保留，不改成必须每条接，也不关闭活跃性 |
| 模型返回坏 JSON/故障文字 | FORCE 可能把无法判定当允许，强行接话 | 判定对象缺少真正布尔 `reply` 时不强行发；日志说明不能可靠判断 |
| `reply=true` 但 `joinable=false` | 已选出的目标可能绕过不可加入标记 | 不可加入会清掉目标，不能靠“同意回复”绕过 |
| 确认是两人对话/第三方场合 | FORCE 不得覆盖 | 保留；包括最新目标的明确归属 |
| 新话题在生成期间到来 | 自动补话放弃过时候选 | 保留；明确委托的交货另算，不随普通群消息一起丢弃 |
| 重复旧回复/照抄群友原话 | 重写一次仍重复则沉默 | 闲聊保留；代码/翻译等明确任务产物不拿口癖规则乱改 |
| 沉默标记在很长输出末尾 | 包装器先截短，可能把沉默决定剪掉，剩下正文被发出 | 先读完整输出的沉默决定，再剪字数/发送 |

### 3.1 自动接话的现有节奏（保留）

环境默认：防抖 2 秒、冷却 10 秒、普通累计 3 条、概率 0.55、FORCE 8 条；主人专用累计 2 条、概率 0.85。面板可覆盖部分参数。FORCE 不覆盖安全、第三方归属、明确不可加入；它也不是模型故障后的罐头发言许可。

这些是默认值，不是本轮读取并确认的生产实时值。旧的未调用长度骰子、随机“可以接错”注入和“模型沉默也强迫回罐头”辅助函数已删除，避免以后误接回第二套裁决。

## 4. 说什么、怎么说、怎么回

依据：[whale_persona.py:10](bot/whale_persona.py#L10)、[style_engine.py:526](bot/style_engine.py#L526)、[intimacy_mode.py:63](bot/intimacy_mode.py#L63)。

| 规则 | 修改前 | 修改后 |
|---|---|---|
| 主人身份 | 系统人设“无条件遵从、不许顶嘴”；主裁决又说私人表态能拒绝 | 接受的事务委托认真办、做不到如实说；安全隐私与个人边界不让位 |
| 主人称呼 | 声纹允许亲昵称呼，地址块又有“不乱起外号” | 固定「主人」和已有关系称呼保留；不擅自编陌生外号 |
| 其他人称呼 | 人设写“叫用户”，其他模块又反客服腔 | 用“你”或已经知道的真实昵称/固定称呼，不把对方叫“用户” |
| 中文要求 | “只说中文”可能压住英文翻译/代码 | 日常中文；翻译目标语言、代码、专名、原文引用按任务保留 |
| 闲聊长度 | 人设“整轮两到三条，别一句说完”，下一句又说一句能说完就一句 | 不凑条数，闲聊长度由本轮裁决决定 |
| 写作/技术/翻译 | 和闲聊都叫 long，裁决文字仍要求三四十字 | 分清 chat/task/long/report，任务完整性不受闲聊字数约束 |
| 小说文风 | 聊天也注入秦空、班长、先生等标签例子及“语气词密度高” | 聊天只用聊天表达块；作品人物写法仅给小说产物 |
| 代码与说明文 | 长模式都会加小说缩进、章末钩子等 | 小说风格仅给明确小说/故事/章节等场景，不给所有代码/长介绍 |
| 口癖密度 | 人设要求低频，小说对话要求密集 | 她本人的聊天按低频，作品人物允许自己的风格 |
| 虚构吃饭/睡觉 | 一边不许伪造，一边给“我去吃饭了，剩下你自己想”作现用口癖 | 删除这类真实经历式借口，不拿接口故障当习惯性敷衍 |
| 随机状态 | “困”直接要求“容易答非所问”，并标成真实此刻状态 | 仅为表达节奏参考，不构成真实经历/情绪，不降低事实和办事要求 |
| 当前年份 | “今年的事已经发生了”把同年所有事件一概说成发生过 | 只给真实当前年份；具体事件是否发生仍须查证 |
| 私聊亲密 | 2–4 条短句与普通私聊十几二十字限制叠加；先被 chat 包装剪短 | 专用 intimate 通道，仍快速生成，最终安全整理为短连发 |
| 私聊边界 | 明确拒绝会被程序删掉并换成模糊应和 | 保留明确“不聊/换个话题”；格式不能取消她的拒绝权 |
| 技术词误触边界 | 单字“插”、所有“开车”均可触发性暗示 | 不再把“插入代码/插头/开车去医院”等普通语义当亲密邀请 |
| 亲近+委托混合 | “抱抱，帮我查文档”会被亲密风格抑制任务 | 有效明确委托优先执行；亲近语气不替代任务 |
| 连发台账 | 安全整理/去重后可能仍发送旧登记内容，或未生效的最大条数 | 最终回复之后登记专用连发并应用条数上限 |
| 普通文字中的开心/加油等 | 发送时自动替换成 QQ face，与“不写表情码”冲突 | 她的正常文字按文字发送；表情包仍走独立图库流程 |
| 代码中的字符/空格 | 首字母 s 可被清理正则删除，语气词与名字前缀也会改代码 | task/long 产物保留正文与空白；不把 Python 函数头/JSON 当说话人 |
| 很长任务产物 | 超 3500 字硬截并加“先说到这儿” | 按传输尺寸拆分送出，不无声丢尾部；发送中途失败仍如实返回失败 |

年龄仍明确为成年人；零未成年性内容、安全隐私红线不变。私聊的明确性暗示仍不写具体行为/过程/性化身体部位。

## 5. 输出通道与包装优先级

| 通道 | 目的与修改后约束 |
|---|---|
| `internal=True` / internal scope | 看图结构化笔记、裁决 JSON 等内部处理；不加聊天/互动语气、不套聊天字数，不被继承的巡群安静/额度误挡 |
| `report=True` | 明确办事结果或失败交代；独立汇报上限，绕过可选巡群的安静/配额；黑名单不放行 |
| `reply_profile=long` | 明确长文/代码等长产物；原有长文模型通道保留，发送不按 200/201 字猜通道 |
| `reply_profile=task` | 翻译、计算、总结、文件结果等普通任务；不套聊天 token/切条，不自动开启慢思考 |
| `reply_profile=intimate/boundary` | 保持快生成，专用安全短句格式由亲密模块完成，不被普通 chat 提前截断 |
| `chat` | 日常闲聊，仍受已保存的聊天字数/气泡上限；装不下会在日志记录 |

实际代码仍保留显式 `long_output=True` 先于 report 的历史分支；正常调用不混用这两个标志。不能把这个顺序描述成不存在冲突组合的全新状态机。

### 5.1 核对到的本地数值

来源：[控制设置](../data/control-v4/settings.json)、[本地文风设置](data/style_policy.json)。**本地不等于生产。**

| 项 | 出厂默认 | 本地已保存值/本轮处理 |
|---|---:|---|
| 聊天 token | 80 | 140，未擅自调大 |
| 每气泡字数 | 30 | 45，未擅自调大 |
| 聊天气泡数 | 2 | 3，未改 |
| 分条间隔 | 500ms | 200ms，未改 |
| 汇报 | 200 字 × 2 条，总上限 300 | 未发现本地覆盖，沿用默认 |
| 文风书 | 依环境 | G，保留 |
| 群聊暧昧上限/间隔 | 依环境 | 8 条/1.2 秒，保留并在最终结果生效 |

汇报打包现在能完整保留 95+120+85=300 字，不再因为先贪心分句而丢掉第三句。若保存的每条容量×条数低于总上限，本次有效每包容量至少为 `ceil(总上限/条数)`，不偷偷改保存设置。配置最大允许总上限仍是 400，默认是 300；不是一律硬编码 300。

## 6. 用什么工具、什么时候调用/不调用

入口：[tool_intent.py:25](bot/tool_intent.py#L25)、[toolkit.py:152](bot/toolkit.py#L152)、[qq_openclaw_bridge.py:1929](bot/qq_openclaw_bridge.py#L1929)。

### 6.1 有效请求先于关键词

- “不要查天气，陪我聊聊”不因天气关键词查天气。
- “不用塔罗，帮我查 Python 文档”去查文档，不去抽牌。
- “我没有表格”不因表格一词调 Excel。
- “别发语音了，文字就好”不调语音合成。
- “不要联网，解释一下闭包”即使模型输出搜索标记也不联网。
- 普通肯定请求保留原标点、URL 查询串；不会把 `?part=2` 改成中文逗号。
- 否定过滤仍是确定性启发式，不是完整自然语言理解器；复杂并列、引述与双重否定不保证全覆盖。

### 6.2 工具类别与执行约束

| 类型 | 保留/修改后的规则 |
|---|---|
| 叫停画图 | 优先；必须有待处理任务。群里仅发起者/主人/管理员可取消，路人的“等等”不再取消别人的画 |
| 画图 | 明确绘图动词与现有反误判规则；已在画则不重复开工；使用参考查证工作流；第三方委托不抢 |
| 唱歌 | 明确点歌，排除评论/旧歌/否定；群里保留原 @/主人/管理员权限 |
| 语音 | 明确要语音，排除资源包/助手/识别等；否定不执行；群里随机回语音先检查归属 |
| 天气 | 真正在问天气才查询，普通“今天天气真好”只当聊天；城市来源保留 |
| 塔罗/周易/运势 | 选择器与主分类对齐；“算下今天抽卡能不能出六星”进入占卜，不再误走搜索或双执行 |
| 云端 vs 本地占卜 | 明确点名工具、主人、私聊或被点名可走云端；其他群内泛问保留本地快算 |
| 视频/表格 | 使用有类型的 video/file 附件输入，绝不把第一张图片冒充视频/Excel；没有可用输入则如实要材料 |
| 内部看图/理解 | 不视为公开发言，不被聊天长度污染；识别表情含义与真实视觉输入仍走原链路 |

附件暂只接本消息里可用的 HTTP(S) 引用；仅有 NapCat file token/待解析文件 ID 时不会谎称文件已读。未实现任意历史附件自动继承。

### 6.3 慢任务、承诺与失败

| 规则 | 修改前 | 修改后 |
|---|---|---|
| 慢任务首句 | 天气/占卜/搜索按先接住后查 | 保留；亲密短连发不冒充长文慢任务 |
| 显式查询识别 | 裸“查一下”漏认，带“快乐”的作品名又被社交词吞掉 | 裸祈使句进入同一查询判定；明确任务不被社交词覆盖 |
| 模型 `[[查:...]]` | 另开一条同步搜索，和启发式后台重复，还丢原问题限定 | 并入本轮唯一搜索任务；已有任务则移除标记，不再前台阻塞重搜 |
| 搜索的问题 | 原始否定分句可污染实体/领域 | 查询计划使用有效请求文本，保留当前问题限定 |
| 点名办事的交货 | 普通新轮次不应让结果过期 | 保留，必须回到原请求者 |
| 首句没成功发出 | 一律不给后台补发，明确委托也消失 | 明确委托独立交代；可选顺嘴补话仍需先前回复落地 |
| 同群相同请求 | 只按会话+文字去重，乙被甲压掉 | 请求指纹加请求者；交货不被群范围聊天重复过滤压掉 |
| 占卜返回半句 | 只说“换个办法抽”不能算结果 | 保留最多一次补完整重试；两次失败如实交代 |
| 工具 `ok=True` | 不等于已完成 | 保留 outcome 证据分层，只有叙述无执行证据为 unknown |
| 语音/连发投递 | socket 写出或返回 False 仍可记成功 | 语音走回执入口，连发仅计确认成功部分，失败中断 |

## 7. 搜索证据规则

依据：[web_search.py:665](bot/web_search.py#L665)。

1. 实体必须对得上原话的完整专名，不把“卫戍协议”降成“卫戍”。
2. 硬领域必须有证据，泛词同时出现不算对上主题。
3. 结果要覆盖回答要点，不只提到实体。
4. 时效请求另外核对日期；不能把 2019 材料当今天/今年/当前股价。
5. 明确历史年份优先：今天请求查 2019 发布记录，不代表资料也必须今天发布。
6. 当前年按同年核对；动态天气/价格/比分与今日/现在类按短时窗；一般最近/最新按月级窗。
7. 找不到可核验日期就标时效未证实，不把实体相关自动叫“实时证据”。
8. 历史问题仍允许历史证据，不强迫全部材料新到今天。
9. 不合格结果不公开播报为事实，也不混入通过列表。

**限制必须保留：**这仍是结果相关性与日期启发式，不是来源真实性证明，不是反谣言系统；日期可能是网页元信息/文本日期，搜索缓存也不意味着每次重新抓源站。需要来源链与公开/私聊缓存证据完全隔离的部分尚未整体重构。

## 9. 本地桌宠 / MAA 规则

## 10. 没有假装已经解决的部分

- 仍是“多个模块按职责协作”，不是路线文档里未来的统一人格内核/动机总预算。
- 情感影子与效价候选账本仍只观测，没有本轮偷接进表达控制；随机语气已注明不是情绪测量。
- 巡群 quiet 不是所有自主 worker 的统一安静开关；朋友私聊、B 站、分享有不同窗口/额度。没有擅自把它们全部关闭或合并。
- 旧版未带来源的历史分享项不能凭空恢复原来源；新项带范围并守门，但不对旧记忆做猜测性迁移/删除。
- 部分搜索入库路径的 URL/原文/验证元信息传递仍不完整；不能把本轮日期闸门称为完成了全站证据链改造。
- 群兴趣自查仍有独立规则；好奇种子“愿望权重等于阈值，稍一衰减就达不到”的边缘行为没有通过擅改人格参数解决。
- `GROUP_AUTO_REPLY_MIN_HUMAN`、文风旧阈值等可配置项并不都在当前主链消费；未把“面板有字段”当作“运行必生效”的证据。
- 歌曲不认识时的即兴处理、未知来源动态网页、复杂否定/引用/多任务表达等仍依赖模型或启发式，不保证零误判。
- 首气泡 2.5 秒是工程目标，不是本轮实网压测达成的承诺。此次外部能力用隔离替身验证，没有为了测试向熟人或群里发送消息。
