# 测试安全守则（重要）

## 事故：2026-11-03

调试群聊上下文时，测试脚本直接调用 `handle_group_message(ws, fake_event)`，
以为只是本地验证。但该函数内部会调用 `send_group_msg`，
**把生成的回复真的发进了用户的真实 QQ 群**。

结果：群里凭空出现「今天被老板骂了」「你说我该不该辞职」等不存在的对话，
用户完全没发过这些话，机器人的对话历史也被污染。

## 规则

1. **任何**会走到 `handle_group_message` / `handle_private_message` / `ask_openclaw` 的测试，
   必须先设置环境变量：

   ```bash
   set QQ_DRY_RUN=1
   ```

   此时 `send_group_msg` / `send_private_msg` 只打印 `[DRY-RUN 未发送]` 日志，
   不会真的发到 QQ。

2. 测试开始前先打印 `QQ_DRY_RUN` 确认是 `True`。

3. 纯函数测试（`_wants_long_mode`、`chunks`、`build_style_block` 等）不需要，
   但要确认调用链不会触发发送。

4. 测试完清理：
   - `data/memory/histories.json` 里的假会话
   - `data/periodic_state.json` 里的假群消息缓存

5. 改数据前先备份到仓库外快照目录（`_backup_<时间戳>`）。
