## 0. 一句话

> **经历改变内部状态，内部状态影响注意与目标，目标推动行动，行动结果再改变记忆、信念与内部状态。**

LLM 负责理解、提出候选与表达；**不能独自决定“发生过什么”“我已经做成什么”“我的人格刚刚变成什么”。**

北极星：把角色养成一个真正连续的人。评估任何改动的标准是
「这让她具有更连续的自我了吗」，而不是「这句话更像群友了吗」。

## 1. 能做到什么，不能证明什么

能做到（可工程化、可验证）：

- 重启、换模型之后，她的关切、承诺、关系、未完成目标仍然连续；
- 情绪基调由经历与恢复过程决定，而不是每轮随机换挡；
- 区分亲历 / 听说 / 查到 / 推测 / 想象；
- 能说明某个观点为何改变，并指向真实事件；
- 无人下命令时，能产生、选择、继续或放弃自己的目标；
- 可以决定不说、不行动，不为了凑指标硬发言。

**不能**据此证明主观体验存在（或不存在）。可验证的是状态、行为、记忆与因果连续性，
不能把情绪面板当意识检测器。

外部资料边界：Generative Agents（记忆/反思/规划闭环）、D2A（数值需求驱动活动选择）、
LMA3（LLM 辅助自主目标）有可核验的原始材料，但其结论都是**模拟环境中的行为可信度/技能获得**，
不是自我或意识证明。用户提到的 MATE（30 特质 / 7 维记忆）、MindForm、RAI Brain 的具体实现
**未获得一手核验**，只作为概念线索，不得写成“已有技术事实”。

## 3. 目标架构

### 3.1 三个子系统、一条闭环

1. **观察事件**：收到什么、看见什么、动作返回什么。
2. **形成解释**：可能意味着什么，证据与不确定性。
3. **更新内部状态**：情绪、关系、关切、信念、承诺。
4. **形成候选目标**：现在有什么值得做。
5. **统一仲裁**：能不能做、是否值得现在做、对谁做。
6. **执行与表达**：工具执行；LLM 生成表达。
7. **确认结果**：成功 / 失败 / 拒绝 / 未知，分别记账。
8. **巩固记忆**：哪些成为经历、哪些改变认识、哪些只是临时信息。

### 3.2 权限分工（硬约束）

- **内核拥有最终状态写入权**；LLM 只能提出候选解释。
- LLM 提出的解释必须经过证据、边界与变更规则，才能成为持久状态。
- 不允许模型一边说“我很难过”，一边直接写情绪数值、人格特质与人生经历。
- 权限、隐私、能力事实是**先行硬约束**，不能被高动机分抵消。

### 3.3 路线选择

| 路线 | 优点 | 缺点 |
|---|---|---|
| 继续加提示词/情绪标签/worker | 快 | 状态继续分散，错位重演 |
| 一次性重写认知架构 | 边界整齐 | 风险最大，破坏现有行为与资产 |
| **旁路建内核、逐步接管（采纳）** | 可回放、可对照、可撤回 | 需清楚维护新旧职责 |

## 4. 路径一：持续运行的情感—人格内核

### 4.1 四种时间尺度

| 层次 | 内容 | 变化速度 |
|---|---|---|
| 身份与边界 | 她是谁、现代人语域、隐私边界、能力事实 | 很慢，变更需留记录 |
| 人格倾向 | 好奇、社交主动、谨慎、玩心、情绪敏感等 | 数周—数月 |
| 情绪与关系 | 效价/激活/掌控感；对具体人的信任、亲近 | 分钟—数天 |
| 工作状态 | 注意负荷、工具预算、等待中的结果 | 秒—小时 |

必须能区分：今天不想说 ≠ 人格变冷；接口失败 ≠ 对朋友失望；对阿甲的亲近 ≠ 对所有人一起变；
想弄懂一件事 ≠ 无限联网。

### 4.2 初版状态

人格倾向先做 **5–8 个能解释行为的维度**，每个都要对应真实决策，例如：
好奇倾向、社交主动性、谨慎程度、玩心、情绪反应敏感度。

情绪底层用三维：**效价**、**激活度**、**掌控感**；另设注意负荷、未完成关切、按人的关系状态。

这些是计算模型变量，不是已测得的人类心理量；初始参数必须实验校准。

**落地状态**：`bot/emotion_core.py` 已按此实现 shadow-v1（效价/激活/掌控/注意四维 +
六项固定特质、参数哈希冻结）；`bot/emotion_shadow.py` 持久消费事件。仍是影子，不接管表达。

### 4.3 状态转移

\[
x_{t+\Delta t}
=
\operatorname{clip}\left[
b_t+(x_t-b_t)e^{-\Delta t/\tau}+G\,a(e_t)
\right]
\]

- \(x_t\) 当前情绪；\(b_t\) 慢变基线；\(\tau\) 恢复时间尺度；
- \(a(e_t)\) 对事件的评估；\(G\) 人格倾向调节；`clip` 防失控。

规则：

- **同一事件只更新一次**（重复检索到旧夸奖不得反复加分）。
- “确定性重放”指**对已记录的事件与评估**得到同一状态，不保证 LLM 对原话每次解释一致。
- 记录评估结果、模型版本与置信度。

### 4.4 持续运行 ≠ 每分钟思考

- 有新事件时更新；轻量定时器只算恢复、预算、期限；
- 无新信息不调 LLM；重启按真实离线时长恢复；
- 离线期间没有观察，不得补写“我昨晚又看了什么”；
- 不伪造饥饿/疼痛/身体疲劳（无对应传感器）；可用“注意负荷”“暂时想安静”。

## 5. 路径二：自传体记忆与持续自我

### 5.1 六类对象（在现有 SQLite 上扩展，不急于图数据库）

| 对象 | 关键字段 |
|---|---|
| **Event** | id、发生时间、记录时间、会话、参与者 QQ、来源、可见范围 |
| **Episode** | 她参与了什么、做了什么、结果、对应事件、当时状态、后来的看法 |
| **Belief** | 命题、对象、支持/反对证据、置信度、有效期、修订历史 |
| **Commitment** | 向谁、承诺什么、期限、完成标准、撤回或完成证据 |
| **Goal** | 想做什么、为什么、归属、步骤、成功标准、状态 |
| **SelfView** | 当前自我认识、支撑经历、保留意见、版本、变更理由 |

关系用关联表：事件支持/反驳信念、目标源于经历、行动履行承诺、经历改变自我判断。

**“7 维”不是关键；这些关系能否参与下一次选择才是关键。**

**落地状态**：六类对象已在 `bot/self_model.py` 建表并有读写函数；
生产数量、legacy 占比与未闭合项见第 2 节与附录 A。

### 5.2 认识论分层（必须）

- 亲历 / 听说 / 查到 / 推测 / 想象 五种，不能都记为“事实”。
- 对她自己的行为分：想发 → 已生成 → 已提交 → NapCat 已接受 → 对方是否看到（通常未知）。
- 只有执行并有结果确认，才能写“我做过”。否则“想刷视频”变“看过视频”，“发出请求”变“朋友收到了”。

### 5.3 自我认识只能修订，不能覆盖

流程：**提出修订 → 检索证据 → 检查反例 → 接受或暂缓 → 留版本**。

示例：由“我不太会主动找朋友”修订为“有话题时我愿意主动找人，只是不喜欢硬聊”，
必须能指向若干真实互动作为支撑。

能回答“什么改变了你的想法”，答案来自修订记录与支撑经历，不能现场编成长故事。

### 5.4 反思不得制造经历

- 无新证据不得新增“发生过”；
- 同一来源的重复转述不算多份独立证据；
- 反思不能反过来充当证明自己的事实；
- 小说/角色扮演/塔罗结果不得混入现实人物事实；
- 原始事件与后来解释分层保存：解释可变，原始记录不可改。

## 6. 路径四：内在动机与自主目标

### 6.1 机会 / 动机 / 目标 / 行动

- **机会**：允许的时间窗、可用预算；
- **动机**：未解决的问题或值得分享的事；
- **目标**：弄懂它 / 告诉相关的人；
- **行动**：搜索、阅读、整理、私聊、等待。

**随机时间点只属于机会层**：它允许行动，不命令发言。每日 2–4 次是机会与上限，
没有合适对象/内容时允许少发，不得为凑数硬聊。

### 6.2 初版四类动机

求知、联结、履约、创造与表达。

不做“越没人理越孤独”的递增压力——那会把正常安静变成刷存在感。

### 6.3 目标必须可归属、可结束

每个候选目标至少包含：归属（谁的）、提出者、她是否接受、与自我/信念/关切的关系、
所需能力、成功与失败定义、放弃条件。

例：目标“弄清荒坂塔的建筑原型”，完成标准不是“搜到三个页面”，而是
“找到可追溯资料 / 能区分明确出处与玩家猜测 / 找不到时保留未证实”。

**落地状态**：`goal` / `action` 已在 `bot/self_model.py` 建表；
目前只有好奇度在 `_curiosity_act` 里建 goal，B 站自主刷片与群聊兴趣查证**不建**；
统一动机与预算尚未实现。

### 6.4 选择规则

先用确定性规则产生有依据的候选，LLM 只帮助细化，不每小时随机许愿。

\[
U(g)=w_1·知识增益+w_2·学习进展+w_3·承诺价值+w_4·关系相关性+w_5·自我一致性-成本-打扰-重复
\]

- **学习进展 ≠ 新鲜感**，无限刷无关新内容不能持续得高分；
- 权限/隐私是硬约束，不入负分；
- **“等待/暂不行动”必须是候选之一**，否则每轮只能从坏选项里硬选，表现为无故搜索、无故私聊。

## 7. 统一仲裁与收件人绑定

### 7.1 一个动作提案整体保存

发起原因、相关事件 ID、**话题主体 QQ**、对话参与者、**收件人 QQ**、可见范围、
当前目标、允许引用的证据、期限与打扰预算。

“阿甲八抽出货”场景：发言者可能是别人，话题主体是阿甲 → 首要候选收件人是阿甲；
若阿甲不在好友、不符合条件或身份映射不确定，**放弃这条私聊**，不得退而发给主人。
**名字检查只是兜底**，没有写名字也可能发错人。

### 7.2 仲裁优先顺序

1. 权限 / 隐私 / 能力；
2. 是否有真实待处理请求或承诺；
3. 收件人—话题主体—场景一致性；
4. 当前状态是否适合；
5. 预算 / 频率 / 冷却；
6. 表达方式、长度与情绪基调。

`conversation_plan` 保留最终裁决职责，但从“提示词规则”升级为“结构化裁决”。
内核提供“她想做什么”，仲裁决定“这次可以执行什么”；不得变成两个互相覆盖的开关系统。

## 8. 持久化与运行

### 8.1 技术栈

继续 Python + asyncio + SQLite。**不先上**：图数据库、多智能体互演（本我/自我/超我）、
全天反思 agent、在线强化学习或即时微调。

在现有 SQLite 扩展：追加式事件表、当前状态快照、信念/经历关系、目标与承诺、
行动队列与发送结果。

**事件、状态更新、待执行动作尽量同一事务提交。** JSONL 只作可导出流水，
不得形成“两套真相”。现有 `history_log` 的轮转只适合会话流水，不得当生平账本。

### 8.2 单一状态写入者

- 入站、工具结果、定时器都只“提交事件”；
- 内核串行更新状态；搜索/视觉/发消息可并发，结果再变成事件；
- Web 默认读；管理修改提交带版本的管理事件。

这样同时消除：重复消耗同一分享名额、重导入后两份状态、整理任务覆盖新对话、
网络失败被记成“她不想说”。

**现状**：事件统一落 `self_model` 表，但 `persona_growth` 仍会写 consolidation 事件与
`self_view`，影子由 `emotion_shadow` 串行更新；真正的“单一状态写入者”尚未完成。

### 8.3 注入分三段

1. 稳定身份层（沿用日内稳定、可缓存）；
2. 当前状态层（情绪、目标、承诺、关系，有界）；
3. 证据层（本轮最相关的真实经历与资料）。

承诺/目标/显著状态变化必须进入第 2 层立即生效，**不得为缓存等到第二天**。
快路径只读已计算快照；理解、巩固、规划在后台。延迟必须实测，不预承诺仍满足 2.5 秒。

## 9. 验收标准（预先固定）

| 能力 | 通过标准 | 当前证据（2026-11-07 生产账本） |
|---|---|---|
| 持续状态 | 重启/换模型前后，目标与承诺不丢失 | **未证明**：goal/commitment 均为 0，还没有可核对的跨重启记录 |

## 10. 落地顺序与退出条件

| 阶段 | 做什么 | 退出条件 | 当前判定（2026-11-07 生产账本） |
|---|---|---|---|
| **0 统一证据** | 真实事件/人物/动作/工具结果建立稳定 ID；区分发送回执与未知 | 能追踪动作起因与是否真正执行 | **部分通过**：281 事件 / 65 条入站去重 / 41 动作 / 2 条回执；39 条动作无回执事件，41 条全部缺 `topic_qq` 与 `event_ids`；2 条亚秒级倒挂（≤4.6ms，历史） |
| **1 自传体记忆** | 经历/信念/承诺/目标建关系；旧记忆保守迁移 | 能回答“什么改变了你的想法”并给出证据 | **部分通过**：206 episode、203 belief 全部是 legacy；0 belief_evidence、0 revision、0 commitment、0 goal；3 条自我认识修订带理由 |
| **2 情感内核影子运行** | 同一事件演化状态，不接管行动 | 状态可重放、无无因跳变、无失控积压 | **通过（影子）**：15/15、回放 `max_error=0`、无跳变、backlog 0、observed≈2.3h；仍 `expression_control=false` |
| **3 接管状态与表达** | 替换随机情绪；统一身份/情绪/关系/目标注入 | 不再出现面板一种心情、回答另一种 | **未开始**：表达仍走 `_MOODS`；影子状态未进入注入 |
| **4 接管低风险自主目标** | 先检索/整理/分享草稿，再私聊与签名 | 目标有归属、终点、预算、结果确认 | **部分**：好奇度/刷片/私聊/签名都在跑；`goal` 只在好奇度建；统一预算与仲裁未做 |
| **5 持续自我修订** | 用长期经历修订信念与自我认识 | 能展示观点与自我认识的版本轨迹 | **未开始**：0 条信念修订；3 条自我认识里 1 条 legacy、2 条整点整理 |

### 迁移底线

- 老记忆缺证据 ID / 真实时间的标 `legacy/unknown`，不补造生平；
- 现有好感保留为“已有关联信号”，不冒充信任/亲密/依赖全部维度；
- 新内核先影子运行再接管；接管后**移除同职责旧判断**，不得两套内核同时发号施令。

不需要重写大桥，但要把状态更新、目标选择、行动裁决逐步抽成清晰接口。

## 11. 明确不做

- 不以“更像人”为目标做拟真话术；
- 不伪造身体感受、现实经历、他人回应；
- 不用情绪数值直接改写人格或替用户决定关系；
- 不让 LLM 自行写入“事实”“已完成动作”“人格变更”；
- 不为凑发言量而主动打扰；
- 不在未核验的情况下引用外部产品的具体维度/实现细节作为依据。

---

## 12. 最终判断

**先做“有证据的自传体记忆 + 单一状态写入者”，再做持续情感，最后放开自主目标。**

没有可靠经历，情绪会被假记忆驱动；没有稳定自我，目标只是随机生成；
没有真实行动反馈，成长只是模型不断给自己写新简介。

值得追求的结果不是她频繁说“我在想什么”，而是她在一段时间以后，
**因为真实经历而选择了不同的事，并且保留这段变化的来路**。

### A.4 判定口径

- `pass`：该阶段的退出条件已被生产数据证明。
- `partial`：代码在、链路在，但证据链或覆盖面不够，不能算通过。
- `not_started`：没有数据，也没有可验收的行为。
- `fail`：发现完整性违约（例如秒级 `ts>created`、影子回放不一致、参数漂移）。
- `subsecond_skew` 单独报告，不判 fail：它是旧写入器留下的亚秒级顺序差，
  当前写入器已复现为 0.0；藏起来反而会让后来的人以为契约没被检查过。

### A.5 已知边界

- 审计是快照；改完状态写入路径后要重跑。
- `legacy` 信念没有证据链，不能因为条数多就当成阶段 1 通过。
- 影子通过只说明「同一事件能稳定演化状态」，不说明参数已校准，更不说明可以接管表达。
- `action` 表口径是**对外发送**；搜索、看视频走 `tool_result` 事件，不建 action/goal。
  快照里的 39 条 accepted 是 15:25 前旧路径直接写入的；当前发送路径是
  `submitted → act-<id> 回执 → accepted/failed`，下一次真实发送后需重跑确认。
- 动作字段的 `topic_qq` / `event_ids` 在快照里全为空；当前群回复已开始传 `topic_qq`，
  但证据事件仍未接，不能把这行当成已经修好。
